The later [real LeanCTX evaluation](real_leanctx_evaluation.md) supersedes
this report's missing-executable limitation. The historical results below
remain unchanged for traceability.

## Scope and evidence

Reviewed `results/ollama_llama3_1_8b_swe-bench-lite_20260909_154614`, including
JSON artifacts, complete agent transcripts, coverage diagnostics, and all
eight generated plots. This is one instance, not a run of all SWE-bench Lite.

The supplied run reported 66,883 Full tokens and 80,153 RAW tokens using a
client tokenizer. Summing saved provider usage gives 64,982 and 73,442:
11.5% savings rather than 16.6%. Both arms missed method Top-5.

## Confirmed defects corrected

- Ollama prompts were hitting the implicit 4,096-token context limit. Native
  requests now explicitly set the same 16,384-token capacity for both arms;
  saturated responses enter the existing context-reduction path.
- Graphify's index omitted nested functions. AST enrichment now includes
  their qualified names and source spans without inventing call-graph edges.
- Agent4SR's bare nested names and single-colon Python paths were not resolved.
  Resolution now uses the source index and traceback evidence. Replaying the
  original RAW answer recovers its candidate for `_TR56._f`.
- Coverage attributed tests to the SymPy runner wrapper. The coverage plugin
  now assigns contexts to test functions in test files. A real recollection
  observed 40 passing tests and two failing tests; Ochiai returns candidates.
- Coverage serialization unnecessarily duplicated large scope records. The
  saved matrix preserves line/test contexts and reduces this instance's
  export from about 416 MB to 7.4 MB.
- Feedback restoration confused repeated lines and misplaced missing prefixes.
  It now aligns occurrences in source order, updates protected coordinates,
  rejects overlapping/out-of-bounds prunes, and makes at most two audit calls.
- Method retrieval documents could include the following unrelated function.
  They now stop at the AST end of the indexed method.
- Exact method names were buried behind substring matches before tool-output
  truncation. On the actual index, `_f` yielded over 6,000 partial matches;
  exact-name lookup now returns the single `_TR56._f` definition. Nested
  tool-call expressions are rejected instead of being treated as query text.
- Headline token accounting now uses returned provider usage where available;
  client context counts remain explicitly approximate for Llama.
- Complete prompts, responses, errors, context texts, coverage output, source
  snapshots, and per-arm checkpoints are persisted for subsequent review.

Earlier corrections to bounded structural briefings, tool responses, final
ranking parsing, and file-level metric matching remain in place.

## Pipeline invariants

## Final replay after search correction

Both arms were freshly replayed with the same final source version in
`results/verification_20260910_search_fixed`. The raw capture and recollected
coverage were shared; neither arm's LLM output was reused.

| Arm | Actual LLM tokens | Method Top-1 | Method Top-3 | Method Top-5 | Correct rank |
| --- | ---: | ---: | ---: | ---: | ---: |
| Full | 81,332 | 0 | 1 | 1 | 3 |
| RAW | 52,615 | 1 | 1 | 1 | 1 |

Both Agent4SR runs now return five resolved candidates, including
`sympy/simplify/fu.py::_TR56._f()`. Ochiai has two failing and 40 passing
contexts. All requests have recorded responses; provider usage sums agree
with the headline totals. The first five predictions obey the fixed merge
constraint. Full's restored evidence preserves the order of the surviving
78 source lines. No LLM transport errors were recorded.

Full still costs **54.6% more** than RAW. Its Agent4SR costs 52,442 tokens
versus 31,883 for RAW; Agent4LR costs 22,518 versus 20,732. Feedback adds
5,220 and graph expansion adds 1,152. The reference compressor reduces the
initial input from 1,629 to 988 client-token units, but feedback brings it
back to 1,493, and the structural briefing adds 409. This explains why
input compression alone does not establish end-to-end savings.

## Limits

The `lean-ctx` executable is absent. Full therefore uses the explicitly
recorded reference compressor and is provisional. A working parser and
nonempty candidates do not establish correct localization or token savings.
In the earlier feedback-fixed replay, the correct method ranks eighth in Ochiai,
outside its fixed five-entry contribution; Full's Agent4SR does not recover
it, so Agent4LR cannot select it. This is an observed retrieval/model miss,
not justification for inserting the known answer or changing the merge.
The final exact-search correction recovers that missing SR candidate, but
Full's top-ranked choice and excess token cost remain unsuccessful outcomes.

Passing the regression suite does not prove that the project has no defects.
Generalization requires additional instances and real LeanCTX verification.
